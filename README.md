# Intent-Slide

**슬라이드보다 먼저, 당신의 의도를 묻습니다.**

누가 보고, 무엇을 이해하고, 어떤 행동을 해야 할까요? Intent-Slide는 짧은 질문으로 전달 방향을 함께 정하고, 그 의도를 근거와 편집 가능한 슬라이드로 완성하는 로컬 작업실입니다.

- **의도를 먼저:** 첫 이야기에서 이해한 의도를 요약하고, 방향을 바꿀 핵심 질문을 한 번에 최대 3개 제시합니다. 선택하거나 자유롭게 답한 뒤, 핵심 메시지·청중의 변화·이야기 순서·시각화 원칙을 확인합니다. 이미 충분한 요청에는 불필요한 질문을 반복하지 않습니다.
- **조사 과정이 보이게:** 검색·열람 활동과 실제로 저장된 원문·위치 확인 발췌·주장 연결 수를 구분해서 표시합니다. 출처 사이트, 원문 열기, 이력과 결과의 로컬 저장 위치를 확인할 수 있습니다.
- **10가지 전달 디자인:** 시그널·도약·프레임·프루프·마일스톤·아키텍트·브리핑·공감·포커스·스파크 중 선택합니다. Slide Master 구조를 참고하되 사용자의 메시지와 근거에 맞춰 비교·차트·흐름·관계를 설계합니다. 선택 화면의 미리보기는 구성 예시입니다.

의도 요약과 전달 전략은 승인 전까지 제안입니다. 사용자가 확인·수정하고 승인한 내용을 기준으로 다음 단계로 넘어갑니다.

GitHub에서 클론하고 실행 파일을 열면 로컬 작업실이 시작됩니다. **Windows 10·11 x64 · Mac Apple Silicon · Intel**용 실행 환경과 기본 Codex를 포함합니다. 단계별 입력·출력, 승인할 체크포인트, 검증에 따른 전체 진행률을 확인할 수 있습니다.

## 시작하기

```sh
git clone https://github.com/Ryan4090/intent-slide-local.git
```

- **Windows:** 폴더의 `Start Intent-Slide.cmd`를 엽니다.
- **Mac:** 폴더의 `Start Intent-Slide.command`를 엽니다.

내장 환경을 준비한 뒤 로컬 페이지가 자동으로 열립니다. Python·Node.js·npm·PowerPoint·LibreOffice·기본 글꼴을 별도로 설치하지 않습니다. 로컬 HTTP 서비스가 시작되면 Codex 연결을 자동으로 확인합니다. 기존 로그인이 있으면 AI 선택 없이 바로 시작하고, 처음이라면 화면의 **Codex 계정으로 로그인** 버튼으로 공식 인증을 진행합니다. 로그인을 마치면 자동으로 작업실로 이동합니다. Git clone 자체는 코드를 실행하지 않으므로 실행 파일을 한 번 여는 단계는 필요합니다.

설치 준비는 저장소 안의 파일만 사용합니다. AI 로그인·모델 실행·웹 리서치는 인터넷과 본인 계정이 필요합니다. 계정이나 유료 이용 권한을 배포본에 포함할 수는 없습니다.

내장 실행 환경을 포함한 현재 배포 파일은 약 **1.9GB**입니다. Git 이력과 압축 해제된 실행 환경까지 보관하므로 실제 디스크 사용량은 더 큽니다. 첫 실행에서는 포함된 파일의 무결성을 확인하고 해제합니다.

**현재 MVP는 Codex 전용입니다.** 연결된 Codex가 제공한 모델과 추론 설정을 선택할 수 있습니다. Claude Code 연동은 MVP 이후 추가할 예정이며, Gemini CLI·OpenCode는 현재 연결 선택지에서 제외합니다. 실제 계정 검증 및 기능 제한은 [AI 호환성](docs/local-mvp/AI_COMPATIBILITY.md)과 [검증 현황](docs/local-mvp/VERIFICATION.md)에 구분합니다. 모든 AI 서비스의 구독을 공통 인증으로 재사용한다는 의미는 아닙니다.

자세한 실행·저장 위치·문제 해결은 [설치 안내](docs/local-mvp/INSTALLATION.md)를 확인하세요.

## 세 단계, 다섯 체크포인트

```mermaid
flowchart LR
    A["① 의도·내용 협의"] --> G1{"내용 확정 · G1"}
    G1 --> B["② 리서치·분석"]
    B --> G2{"근거 확정 · G2"}
    G2 --> C["③ 디자인·제작"]
    C --> G3{"디자인 확정 · G3"}
    G3 --> D["슬라이드 작성"]
    D --> G4["파일 검사 · G4"]
    G4 --> G5["최종 이미지 검토 · G5"]
    G5 --> E["검증된 PPTX 다운로드"]
```

| 단계 | 입력 | 확인 가능한 출력 | 전체 비중 |
|---|---|---|---:|
| 의도·내용 | 요청, 자료, 대화 답변 | 목적·청중·성공 기준, 슬라이드별 구성, 조사할 질문 | 20% |
| 리서치·분석 | 확정 내용과 조사 범위 | 핵심 결과, 원문 출처·발췌, 수치·계산, 슬라이드 메시지 | 35% |
| 디자인·제작 | 승인한 내용·근거·디자인 | 슬라이드, 발표 노트, PPTX, 실제 렌더, 검사 결과 | 45% |

전체 %는 **검증된 유효 결과**의 가중 합계입니다. 작성된 슬라이드 수와 최종 검증 완료율을 따로 보여줍니다. 입력이나 결과 파일이 바뀌면 관련 승인이 무효화되고 재검토가 필요합니다. 시간이 지났다는 이유만으로 100%가 되지 않습니다.

작업 중 질문에 답하고, 내용·근거·디자인을 확인해 승인하세요. 수정할 내용은 작업실에서 요청하면 이력이 남습니다. 완료 후에는 현재 검증된 결과의 PPTX와 페이지 미리보기를 열 수 있습니다.

## 데이터와 실행

- 작업 상태와 산출물은 저장소 안의 로컬 실행 폴더에 저장됩니다. 서버를 재시작해도 이어서 확인할 수 있습니다.
- Codex에는 해당 단계의 요청과 자료가 전달됩니다. 제공한 자료만 사용하는 조사 모드도 AI 모델 호출을 로컬 연산으로 바꾸지는 않습니다.
- 작업실은 `127.0.0.1`에만 열립니다. 외부 서비스로 공개하는 서버가 아닙니다.
- Codex 모델·추론 설정을 바꾸면 다음 작업부터 적용합니다. 서로 다른 도구·모델의 대화를 잘못 재개하지 않습니다.
- 작업 자료·실행 DB·인증 데이터는 배포 대상에서 제외됩니다.

## 지원과 개발

현재 제작 엔진은 `projects/presentation-agent-suite/`에 있습니다. 실제 PPTX 미리보기는 내장 LibreOffice로 PDF를 만든 뒤 페이지별 PNG로 검사합니다. 기본 Pretendard 6종 중 사용하는 서체를 최종 PPTX 안에 원본 그대로 포함하므로 별도의 글꼴 설치가 필요하지 않습니다. G4는 그 최종 파일을 검사하고 G5는 같은 파일에서 만든 이미지를 검토합니다. Microsoft PowerPoint 앱에서의 표시·편집 검사는 별도입니다.

Windows x64·Mac Apple Silicon·Intel의 클론 준비, 내장 Codex 실행, 한글이 포함된 실제 PPTX 렌더, 로컬 세션 검사는 [공개 CI](https://github.com/Ryan4090/intent-slide-local/actions/runs/34030968077)에서 통과했습니다. 플랫폼별 결과와 실제 AI 제작 상태는 [검증 현황](docs/local-mvp/VERIFICATION.md)에 기록합니다. Linux·Windows ARM64·Windows N 등 특수 구성은 현재 지원·검증 대상에서 제외합니다.

이번 버전은 Mac에서 내장 Codex의 실제 한글 2장 제작을 G1–G5·100%까지 확인했습니다. 이전 v0.1.0의 3장 완료는 과거 검증 기록으로 보존합니다. 현재 내장 런타임 버전의 검사와 이전 버전 증거는 [검증 현황](docs/local-mvp/VERIFICATION.md)에서 따로 기록합니다. Claude·Gemini·OpenCode의 실제 계정별 전체 제작은 확인된 범위만 표시합니다.

Intent-Slide 제품 소스는 [MIT](LICENSE)입니다. 포함된 Python·Codex·LibreOffice·PyMuPDF·글꼴은 각각의 조건을 따릅니다. [제3자 고지](THIRD_PARTY_NOTICES.md)와 `vendor/portable/`의 출처·SHA·대응 소스 파일 또는 공식 소스 링크를 함께 제공합니다.

배포에는 제품 실행 파일만 포함하며 기존 비공개 Git 이력·개인 프로젝트·인증 정보는 포함하지 않습니다. [배포 절차](docs/local-mvp/DISTRIBUTION.md)를 확인하세요.
